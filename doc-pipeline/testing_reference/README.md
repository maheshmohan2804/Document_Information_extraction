# PDF Evaluation Pipeline

Automated quality evaluation of PDF extraction pipeline using OpenRouter's Gemini 2.5 Pro.

This tool evaluates the quality of your PDF extractions by using the **full markdown content as ground truth** and comparing it against the extracted structured fields (authors, date, summary, methods, findings).

## Setup

1. Install dependencies:
```bash
npm install
```

2. Configure your OpenRouter API key (choose one method):

   **Method A: Using .env file (Recommended)**
   ```bash
   # Edit the .env file and add your key
   OPENROUTER_API_KEY=your-actual-openrouter-api-key
   ```

   **Method B: Using environment variables**
   ```bash
   # Windows PowerShell
   $env:OPENROUTER_API_KEY="your-openrouter-api-key"

   # Windows CMD
   set OPENROUTER_API_KEY=your-openrouter-api-key

   # Linux/Mac
   export OPENROUTER_API_KEY="your-openrouter-api-key"
   ```

   Get your API key from: https://openrouter.ai/keys

## Prerequisites

Before running evaluation, you need to have extraction files generated by the pipeline. These files are created in `doc-pipeline/src/orchestration/output/` when you run the main pipeline.

## Usage

### Step 1: Generate Extractions (if not already done)

First, run the pipeline to generate extraction files:
```bash
cd ../doc-pipeline/src/orchestration
npm start -- "path/to/document.pdf" --groq-key "your-groq-key"
```

This creates extraction files in `doc-pipeline/src/orchestration/output/` with the format `extraction-{timestamp}.json`. Each file contains:
- Extracted structured data (authors, date, summary, etc.)
- **Full markdown content as ground truth**

### Step 2: Evaluate Extractions

Run the evaluation on existing extraction files:
```bash
npm run evaluate
```

This will:
1. Find all extraction files in `doc-pipeline/src/orchestration/output/`
2. Read the **full markdown content** as ground truth
3. Compare extracted fields against the ground truth using Gemini 2.5 Pro
4. Generate a detailed quality report
5. Save results to `evaluation_results.json`

### Options

**Evaluate only the latest extraction:**
```bash
EVALUATE_ALL=false npm run evaluate
```

**Evaluate all extractions (default):**
```bash
npm run evaluate
```

## Evaluation Criteria

The evaluation uses the **full markdown document as ground truth** and checks:
- **Dates**: Do extracted dates match what's in the ground truth document?
- **Authors**: Are author names complete and accurate compared to ground truth?
- **Document Type**: Does the document type correctly describe the ground truth?
- **Methodologies**: Are research methodologies accurately summarized and grounded in the document?
- **Summary**: Is the summary factually accurate and grounded in the document?
- **Findings**: Are findings/conclusions accurate and grounded in the document?
- **Overall Score**: 0-100 quality score with reasoning

### Key Improvement
The evaluation now uses the **extracted markdown content as the source of truth** rather than comparing markdown vs HTML. This provides a more accurate assessment of whether the pipeline correctly extracted and summarized the document's key information.

## How It Works

1. **Ground Truth**: The pipeline extracts the full PDF content as markdown and saves it in the extraction JSON
2. **Structured Extraction**: The pipeline also extracts structured fields (authors, date, summary, methods, findings)
3. **Evaluation**: Gemini 2.5 Pro compares the structured fields against the ground truth markdown to assess:
   - Accuracy of extracted metadata (authors, dates)
   - Quality of summarization (summary, methods, findings)
   - Factual grounding (whether claims are supported by the source document)

- You can regenerate extractions by running the updated pipeline
- The script automatically sorts extraction files by modification time (newest first)

## Troubleshooting

### Rate Limit Errors (429)

If you see a "Rate limit exceeded" error:

**Quick fix:** Evaluate only the latest extraction
```bash
EVALUATE_ALL=false npm run evaluate
```

**Why this happens:**
- The free tier of OpenRouter/Gemini has strict rate limits
- Large markdown documents use many tokens
- Multiple requests in quick succession can trigger limits

**Solutions:**
1. **Wait 5-10 minutes** and try again
2. **Evaluate one at a time** using `EVALUATE_ALL=false`
3. The script now includes a **10-second delay** between evaluations
4. Consider **upgrading to a paid OpenRouter plan** for higher limits

### No Extraction Files Found

If you see "No extraction files found":
1. Make sure you've run the pipeline first:
   ```bash
   cd ../src/orchestration
   npm start -- "path/to/doc.pdf" --groq-key "your-key"
   ```
2. Check that files exist in `../src/orchestration/output/`
